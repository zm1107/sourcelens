1. Interface overview

The main window has two tabs: Comparison (the daily workflow) and OCR conversion (a standalone converter). Menu bar:

  • File: add files / add folder, export report, exit;
  • Metrics & params: Analysis params… (risk thresholds / workers / fingerprint toggle, with the metrics dialog entry), Metrics…, Enable document fingerprints (checkbox);
  • Settings: Manage typo dictionary (all active entries; add/edit/delete plus space-separated CSV import/export), Query local history on compare (checkbox), Auto-save to history after compare (checkbox), cloud database setup, local data management;
  • Help: User guide (this file), About (version, website https://sourcelens.weibaba.fun, feedback feedback@weibaba.fun).

Main layout: file actions + project name (* required, red hint) + "Analysis params…" button + read-only config summary (thresholds / workers / fingerprint / dictionary count) + "Typo review…" button + file list + compare buttons + six result tabs.

2. Comparison workflow

  1. Add files: multi-select is supported; the file list shows name / size / type / bidder company / status. Del or the context menu removes the selected rows; click a header to sort. Bidder companies are parsed automatically right after loading (fills blanks only, never overwrites): auto-filled cells are shown in blue with the hover hint "for reference, please confirm" and turn normal once you double-check or edit them; unrecognised names stay blank for manual entry.
  2. Maintain bidder companies (history-related): "Parse company names" re-runs recognition any time (again blanks only); double-click a company cell to edit. The project name above applies to the whole batch and is required: while empty the label reads "Project name (* required)" in warning colour with a pale-yellow input box, and comparison cannot start.
  3. Set parameters:
    • High / medium risk thresholds (defaults 60 / 30): changing them re-judges the grouping immediately, no re-analysis needed;
    • Worker count: OCR parallelism;
    • Fingerprint master switch: off skips the fingerprint channel entirely (fingerprint evidence no longer scores).
  4. Choose metric plugins: the "Metrics…" button in the parameter area opens the settings window — every metric can be enabled or disabled with a custom weight (0.00–1.00); enabled weights must sum to exactly 1.00 (100%) — anything else triggers a red warning and blocks saving. Weights drive the style-channel aggregation behind the "similar writing style" evidence item; fingerprint metrics carry their evidence-level notes; metrics marked "(slow)" or "(off by default)" (noise-correlation, rendered line-break comparison) are opt-in — rendered line-break comparison needs local Office. "Restore defaults" resets every toggle and weight. Changes apply from the next comparison.
Scoring (evidence accumulation): the total is the accumulated risk points of all evidence items (0–100) — hard-evidence fingerprint +55 (including matching metadata feature values: author / last-modified-by / company being the same real, distinctive value on both sides — a forgeable field left uncleared and identical is nearly self-evidencing; non-matches or empty values never reduce the score), strong-evidence fingerprint hit rates ≥85%/≥70%/≥50% adding +40/+28/+18, each accepted co-occurring typo +12, identical passages of ≥50 characters +15 each, writing-style similarity ≥85%/≥70%/≥50% adding +12/+8/+4, environment fingerprints +2 per class; rendered line-break agreement below 35% (layout provably divergent) is a cancelling item: −25 and a cap of 25. Totals at or above the high threshold (default 60) → high risk, at or above the medium threshold (default 30) → medium risk, otherwise low risk. Per-pair evidence is itemised on the Evidence tab.
  1. Start comparison: the progress bar advances stage by stage (extraction → fingerprints → segmentation/template removal → features → pairwise → clustering → history), the per-file status column updates live (pending → extracted → extracted·fingerprinted → done) and the timestamped log records every stage for archiving.
    Scanned-page recognition (two modes): the default "fast" mode OCRs only pages with no text layer at all; scanned pages carrying a thin text layer (header, page number, stamp) are analysed from that layer. To OCR those pages in full, tick "Full OCR (deep-scan scanned pages)" in "Analysis params…" — when you press Start, a dialog first reports how many pages need recognition and the estimated time (about 1.25 s/page at 8 threads), and you can skip it for this run only. Progress advances per page as "document i/N · OCR: done/total pages" and the log ends with the text-page / OCR-page split; results are cached per document, so later runs complete in seconds (cancelling mid-way loses at most the current document's OCR work). With many scanned pages, raise the worker count.
  2. Manual typo review: after a comparison, if the active dictionary hits typos that co-occur on both sides, the review window pops up immediately — matching covers the entire text of every document (hits inside shared boilerplate included; wordings found in a single document are not listed). Each row shows the suspected wording, the correct form, the documents it appears in, quoted sentences from both documents (5 characters around the typo, the typo itself in red bold) and page numbers (page A / page B):
    • Documents: the document numbers the wording appears in (comma-separated, e.g. "1,3"); accepted rows score. The column has a fixed width and wraps; the page-A/page-B columns wrap the same way; sentence and verdict columns always show in full;
    • Accept: it really is a typo — the item counts toward this comparison's score (+12 each, a strong same-origin signal); it does not affect future batches;
    • Reject: correct wording as it stands — not scored, and never judged again (long-term); clicking the same button again undoes the verdict;
    • Unhandled (default): not scored this time, no effect on the future;
    • Bulk actions: multi-select rows with Ctrl / Shift, then use "Accept selected / Reject selected" at the bottom (both disabled with no selection);
    • Open any time: the "Typo review…" button in the parameter area reopens the window without waiting for a comparison — it lists every dictionary hit with the current verdict pre-filled, and changes recompute instantly;
    • "Apply and recompute" immediately recalculates totals, verdicts and clustering (no re-analysis); "Later" keeps the current scores and asks again next time.
  3. Read the results (six tabs):
    • Bid-price patterns (shown when prices are detected): a batch verdict, a bar chart of every document's amount (low to high, with differences and ratios) and per-rule mini charts R1–R5 — arithmetic sequence (adjacent differences against the mean) / fixed ratio (ratio scatter with common-discount target lines) / shared trailing digits (last 2–3 digit rows) / multiple relations (multiples of the lowest bid with integer ticks) / spread rate (spread band against the threshold band); red = hit, grey = no hit, chart numbers and the verdict text share one source;
    • Clusters: suspected same-origin groups. Grouping follows the pairwise matrix exactly — any pair whose risk points reach the high threshold joins the same group (connected components), so "high-risk in the matrix yet isolated in the cluster" cannot happen; a group's score is the arithmetic mean of all its internal pairs (hover for the pair list and the grouping rule), a document's score is its highest pair within the group;
    • Pairwise matrix: risk points and verdict (high / medium / low) for every pair, the redder the riskier;
    • Evidence: pick a pair from the drop-down (ordered by risk points); the header itemises the risk points and every evidence contribution, followed by per-plugin hits (co-occurring typos / shared frequent words / shared boilerplate, with complete page lists) and highly similar passages;
    • Fingerprints: the full detail table of every fingerprint metric (metric / status / level / result) across the hard / strong / corroborating levels; "compared, no match" is noted in grey; not-applicable / no-data / switched-off states are each explained;
    • History matches: per-document hits in the local / cloud history database by identity code (historical project / company / file name / time / reporting unit).
  4. Adjust thresholds: change them after the fact and the grouping re-forms instantly.
  5. Export the report: HTML, with a timestamp prefix (YYYYMMDDHHMMSS_SourceLens_report.html), six chapters (clusters / matrix / list / evidence / fingerprints / history).

3. History database

  • Identity code: the SHA-256 of the whole file. Renaming, copying or transferring a file keeps the code; editing its content changes it.
  • Local database: zero-config, data\history.db beside the program; "Query local history on compare" and "Auto-save to history after compare" are on by default. Queries run before writes: records saved this round only take part in matching from the next round.
  • Cloud database (optional): enable it in Settings and fill in the PostgreSQL connection; "cloud history compare" and "auto upload" toggle independently, and the reporting unit is stored with each record. The cloud keeps archive data only (identity codes / fingerprints / occurrence records), never document texts.

4. Typo dictionary

"Settings → Manage typo dictionary" manages all active entries (981 built-in plus your edits): double-click to edit, add, delete (built-in entries can be deleted too) and full CSV import/export — one "wrong correct" pair per line, space-separated; export, edit and re-import to delete entries or fix their direction, with automatic direction checking on import (apparently reversed rows ask for confirmation). Your overlay persists in %APPDATA%\SourceLens\typos_extra.csv (edits) and typos_removed.csv (deletions) and reloads on the next start. Co-occurring typos are a key style-channel signal — the cleaner the dictionary, the more reliable the results.

Dictionary-only detection: typos are judged exclusively by exact dictionary matching (981 built-in entries + your own); the old "4-character length cap" and the "suspected writing" channel (tokenizer-based, too noisy) were removed in 4.0. Entries are exact substring matches, so long entries are equally accurate, and matching tolerates line breaks and small amounts of whitespace inside a word (PDF line-by-line extraction and OCR frequently split words). Matching covers the entire text of every document (typos inside boilerplate count and score too); the review window lists only co-occurring wordings as a same-origin signal — a typo found in a single document is not listed and does not score (each run logs a "typo dictionary" statistics line plus the co-occurrence word list so you can confirm the dictionary is actually matching). Remove any false positive from the dictionary manager.

5. OCR conversion

The "OCR conversion" tab: pick PDF files (multi-select) → output format (txt / docx) and directory → start. Scanned pages are OCR'd automatically; during a comparison, a page counts as scanned when its text is sparse and the page is dominated by a full-page image — scanned PDFs often carry a thin text layer (header, page number, stamp, a few dozen characters) that a character-count-only rule would mistake for a normal text page and silently skip, losing the whole body; such pages are always OCR'd (conversions are cached per file as well).

6. Reading the results

  • Style scores ≥80 suggest the same author, 60–80 are inconclusive, <60 suggests different authors (default thresholds, calibratable);
  • Cross-confirming channels are what count: a high style score plus hard fingerprint evidence is the strongest result; a single corroboration is only a lead;
  • Corroborating evidence (metadata, layout) can be edited or forged — treat it critically; missing metadata does not imply different origins;
  • Noise correlation is experimental: no detected correlation does not imply different origins (compression and binarisation destroy noise information);
  • RSID hits may come from a shared template — cross-check against the template situation;
  • This tool assists human judgement only; the final call always rests with a manual review of the originals.
